# Workflow regression audit — 18 October 2026

The initial regression run passed all 556 existing fast tests. Additional error and concurrency cases reproduced flaws that those tests did not cover. Fixes and new regression coverage are included in this change.

## Findings and fixes

| Finding | Reproduction | Result after the fix |
| --- | --- | --- |
| Failed script actions dropped unfinished scenes | Leave a scene's narration empty but select its media and edit its title; submit an unnamed save or trigger a writer failure | Save validation, rewrite errors and comparison-generation errors retain the unfinished scene, title and media |
| Partial language-generation results were discarded | Generate Hindi successfully, then fail English generation | Hindi remains editable; Write missing language scripts retries English without regenerating Hindi |
| Storage failures escaped the editor | Simulate a permissions failure while saving one script or several selected versions | An actionable error appears in the editor, current edits remain available and the existing library stays intact |
| A group of versions was saved through separate writes | Save several selected versions together | The library update now uses one atomic write, preventing partially saved groups if storage fails |
| Concurrent library edits could overwrite each other | Submit four independent named saves concurrently | All four names survive; save, deletion and clear operations share a library lock |
| Pending submissions left scenes editable and could re-enable render actions | Hold a save response open, then attempt to edit or trigger input updates | Form controls freeze after request serialization; Build and Queue remain disabled and duplicate submissions are rejected |
| Returning to a cached page could leave its controls disabled | Dispatch the browser's persisted `pageshow` event on the pending page | Original control states and labels return; progress state and its timer are cleared |
| API-settings browser audit expected six providers | Run the audit against the current eight-provider UI | Audit assertions now use the provider registry's count |

Successful saves continue to omit intentionally blank narration rows, as before. Failed operations preserve those rows so they can be completed. Existing drafts are retained on a failed rewrite; newly generated languages are retained when no earlier draft existed.

## Verification

- Fast regression suite: **563 passed, 18 deselected**, in 116.91 seconds. Seven additional cases cover generation recovery, unfinished scene preservation, storage failures, group writes and concurrent saves.
- Script browser audit: **9 checks passed**, including the held-response test, desktop/mobile editing, exact renderer inputs and no JavaScript errors. Cached-page recovery is tested using a persisted `pageshow` event; it does not assert every browser's cache eligibility.
- API-settings browser audit: **4 checks passed**, covering all eight providers, validation, network failure, tablet/mobile layouts and saving without JavaScript.
- Scene-editor browser audit: **4 checks passed**, including actual media upload, image/word pairing, errors, Escape, mobile layout and edit/rebuild.
- Real-preview browser audit: **5 checks passed**, including actual FFmpeg rendering, mixed image/video scenes, playback, scene seeking, edits, refresh failure recovery and cache cleanup.
- All executable inline template JavaScript passes Node syntax validation. Python compilation and Git whitespace checks pass.
- Real-video suite: **18 passed, 563 deselected**, in 160.28 seconds. Across both runs, all **581 tests passed**.

All checks use disposable products and test data. Real preview/render checks use silent narration; no provider credits or social publishing accounts are exercised. This audit does not add automatic working-draft persistence: save a named version before leaving the editor.

Browser artifacts are under `out/audit/script-flow/`, `out/audit/api-settings/`, `out/audit/scene-editor/` and `out/audit/reel-preview/`.

## Deletion follow-up

Targeted deletion checks: **24 tests passed**. The disposable Chromium runner `scripts/audit_deletion.py` passes **5 deletion flows**: saved-script confirmation/cancellation, separate draft/library clearing, photo deletion on Save, product deletion keeping exports, and explicit product-plus-exports deletion.

The browser check reproduced and fixed a confirmation bug for saved-script names containing apostrophes. The confirmation text now comes from an escaped HTML data attribute instead of interpolating a name into executable JavaScript. A name containing apostrophes, double quotes and HTML-like text now confirms correctly; dismissing the dialog leaves the library unchanged. Accepted saved-script deletion retains unsaved scene edits. No real products or exports were deleted during testing.
